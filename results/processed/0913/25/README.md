# 0913/25 — 减少权重读取等待

在非 Thor 主机准备了 7,233,650,352-byte BF16 序列化缓存，812 个张量逐一验证成功，位于可丢弃的 /scratch 缓存。

实际后续实验选择了更直接的原始 F32 权重顺序读取，未使用 BF16 派生缓存。Thor 对剩余 2.108 GB 原始数据做顺序预读，用时 55.417 秒，之后 0913/26 和 27 的完整原始权重加载约 4 秒。该加速来自 I/O 方式和 OS 缓存；不能当作 GPU 推理加速。

派生缓存可选用，必须与原始权重加载后的实际参数指纹完全一致才允许进入 profiling。没有安装或修改 Thor 环境。
